# OnlineLearning — платформа онлайн-навчання

> Наскрізний проєкт з дисципліни «Клієнт-серверні застосунки»  
> Тема 3.4 — Платформа онлайн-навчання  
> Стек: **C# / ASP.NET Core Web API / .NET 10**  
> Семестр 7 — монолітна архітектура

**OnlineLearning** — інформаційна система для організації онлайн-навчання, що об'єднує курси, уроки, зарахування студентів, відстеження прогресу, тестування, взаємодію в реальному часі та ШІ-перевірку відкритих відповідей.

Проєкт розвивається за принципом **«моноліт → мікросервіси»**: у 7 семестрі створюється монолітний застосунок із програмним інтерфейсом, базою даних і підсистемою безпеки; у 8 семестрі плануються контейнеризація, спостережуваність та еволюція до розподіленої архітектури.

## Мета проєкту

Розробка багаторівневої інформаційної системи для організації дистанційного навчання, що забезпечує:

- створення та керування курсами й уроками;
- розміщення навчальних матеріалів (PDF, відео);
- реєстрацію, автентифікацію та розмежування прав доступу;
- зарахування студентів на курси та відстеження прогресу;
- проведення тестувань (Quiz);
- обмін даними в реальному часі та сповіщення;
- формування сертифікатів;
- використання ШІ для перевірки відкритих відповідей.

| Роль | Права |
|---|---|

| **student** | Запис на курси, опрацювання навчальних матеріалів, проходження тестів |

Станом на **Етап 1** створено базовий каркас рішення та п'ять проєктів. Поточна фактична структура:

```text
OnlineLearning/
├── .gitignore
├── OnlineLearning.slnx
├── README.md
│
└── src/
    ├── OnlineLearning.Api/
    │   ├── Controllers/
    │   │   └── CoursesController.cs
    │   ├── Properties/
    │   │   └── launchSettings.json
    │   ├── appsettings.json
    │   ├── appsettings.Development.json
    │   ├── OnlineLearning.Api.http
    │   ├── OnlineLearning.Api.csproj
    │   └── Program.cs
    │
    ├── OnlineLearning.Application/
    │   └── OnlineLearning.Application.csproj
    │
    ├── OnlineLearning.Domain/
    │   ├── Entities/
    │   │   └── Course.cs
    │   └── OnlineLearning.Domain.csproj
    │
    ├── OnlineLearning.Infrastructure/
    │   └── OnlineLearning.Infrastructure.csproj
    │
    └── OnlineLearning.Shared/
        └── OnlineLearning.Shared.csproj
```

### Призначення основних директорій

**OnlineLearning.Api**

Відповідає за взаємодію із зовнішніми клієнтами через HTTP:

- контролери та маршрутизація;
- REST API;
- Swagger / OpenAPI;
- middleware автентифікації та авторизації;
- обробка помилок відповідно до RFC 7807;
- SignalR-хаби (плануються у 8 семестрі).

**OnlineLearning.Application**

Містить бізнес-логіку застосунку:

- сервіси;
- DTO;
- інтерфейси;
- валідатори;
- сценарії роботи системи.

Шар створено, але він поки порожній. Наповнення заплановано на Етапі 2.

**OnlineLearning.Domain**

Містить основні сутності та правила предметної області:

- доменні сутності;
- переліки enum;
- базові типи;
- доменні правила.

На поточному етапі реалізовано сутність `Course` у `Entities/Course.cs`.

**OnlineLearning.Infrastructure**

Відповідає за технічну реалізацію доступу до даних та зовнішніх ресурсів:

- Entity Framework Core;
- PostgreSQL;
- репозиторії;
- зовнішні API-клієнти;
- фонові виконавці.

Шар створено, але його наповнення заплановано на наступні етапи.

**OnlineLearning.Shared**

Призначений для спільних контрактів і компонентів, які використовуються різними шарами системи. Наразі проєкт створено, але він ще не наповнений.


### Напрямок залежностей між шарами

```text
OnlineLearning.Api
        |
        v
OnlineLearning.Application
        |
        v
OnlineLearning.Domain

OnlineLearning.Infrastructure
        |
        +------> Application
        |
        +------> Domain
```

Основний принцип архітектури: **доменний шар не залежить від інфраструктури**. Бізнес-логіка відокремлена від деталей реалізації бази даних та зовнішніх сервісів.

## Швидкий старт

### Вимоги

Для роботи з проєктом необхідні:

- **.NET SDK 10.0+**;
- Visual Studio 2022 (17.13+) або Visual Studio Code + C# Dev Kit;
- `dotnet CLI`;
- Docker Desktop — для PostgreSQL і Redis, починаючи з Етапу 2;
- EF Core CLI — для роботи з міграціями на відповідному етапі.

Встановлення EF Core CLI:

```bash
dotnet tool install --global dotnet-ef
```

### 1. Клонування репозиторію

```bash
git clone <URL>
cd OnlineLearning
```

Замість `<URL>` потрібно вказати адресу Git-репозиторію проєкту.

### 2. Відновлення залежностей

```bash
dotnet restore
```

### 3. Налаштування змінних середовища

На наступному етапі планується створення шаблону `.env.example`.

Після його додавання можна буде створити локальний файл налаштувань:

```powershell
Copy-Item .env.example .env
```

У файлі `.env` потрібно буде вказати власні значення паролів та ключів. Реальний `.env` не повинен потрапляти до Git-репозиторію.

**Примітка:** на поточному етапі `.env.example` ще не створено, тому цей крок стане доступним після його додавання.

### 4. Запуск API

```bash
dotnet run --project src/OnlineLearning.Api
```

Після запуску API буде доступний за адресою, яку виведе консоль.

### 5. Swagger

Інтерактивна документація API буде доступна за адресою:

```text
https://localhost:<port>/swagger
```

Замість `<port>` потрібно використовувати порт, указаний під час запуску застосунку.

### 6. Перевірка стану

Після реалізації health checks наприкінці Етапу 1 планується перевірка:

```bash
curl https://localhost:<port>/health
```

### 7. Ручне тестування API

Для ручного надсилання HTTP-запитів передбачено файл:

```text
src/OnlineLearning.Api/OnlineLearning.Api.http
```

Його можна використовувати у Visual Studio або Visual Studio Code з розширенням REST Client.

### Заплановані команди для наступних етапів

Після додавання Docker Compose та налаштування PostgreSQL і Redis планується запуск залежностей:

```bash
docker compose -f docker/docker-compose.dev.yml up -d
```

Підключення сервісів:

- PostgreSQL — `localhost:5432`;
- Redis — `localhost:6379`.

Після реалізації Entity Framework Core та створення першої міграції планується застосування міграцій:

```bash
dotnet ef database update \
  --project src/OnlineLearning.Infrastructure \
  --startup-project src/OnlineLearning.Api
```

Ці команди стосуються наступних етапів і поки не є частиною готового функціоналу.

## Змінні середовища

Секретні дані не повинні зберігатися у вихідному коді та Git-репозиторії.

Для локальної розробки планується використання `.env`, а для production-середовища — Secret Manager або CI secrets.

Структура змінних середовища, яку передбачено для проєкту:

| Змінна | Призначення |
|---|---|
| `ASPNETCORE_ENVIRONMENT` | Середовище виконання (Development / Production) |
| `ConnectionStrings__Default` | Рядок підключення до PostgreSQL |
| `ConnectionStrings__Redis` | Рядок підключення до Redis |
| `Jwt__Key` | Секретний ключ підпису JWT (не менше 32 байтів) |
| `Jwt__Issuer` | Видавець JWT |
| `Jwt__Audience` | Отримувач JWT |
| `Jwt__AccessTokenMinutes` | Час життя access-токена |
| `Jwt__RefreshTokenDays` | Час життя refresh-токена |
| `OAuth__Google__ClientId` | Google OAuth Client ID |
| `OAuth__Google__ClientSecret` | Google OAuth Client Secret |
| `OpenAI__ApiKey` | API-ключ OpenAI |
| `HuggingFace__ApiKey` | API-ключ Hugging Face |
| `Media__ApiKey` | Ключ відеохостингу |
| `Storage__BasePath` | Локальний шлях для зберігання файлів у режимі розробки |

### Приклад майбутнього `.env.example`

```env
# Приклад конфігурації.
# Реальний файл .env НЕ комітимо до Git.

ASPNETCORE_ENVIRONMENT=Development

ConnectionStrings__Default=Host=localhost;Port=5432;Database=online_learning;Username=postgres;Password=CHANGE_ME
ConnectionStrings__Redis=localhost:6379

Jwt__Key=CHANGE_ME_SUPER_SECRET_32_CHARS_MIN
Jwt__Issuer=OnlineLearning
Jwt__Audience=OnlineLearning
Jwt__AccessTokenMinutes=15
Jwt__RefreshTokenDays=7

OAuth__Google__ClientId=CHANGE_ME
OAuth__Google__ClientSecret=CHANGE_ME

OpenAI__ApiKey=CHANGE_ME
HuggingFace__ApiKey=CHANGE_ME
```

> **Увага:** наведені значення є прикладами. Реальні паролі, секретні ключі та API-ключі потрібно вказувати локально. Не публікуйте їх у репозиторії.

Файл `.env.example` є запланованим шаблоном і має бути доданий до репозиторію окремо.

## Безпека

Під час розробки системи передбачено використання практик безпечної роботи з даними.

### Захист секретних даних

Реальні секрети не повинні зберігатися у Git-репозиторії:

- паролі PostgreSQL;
- JWT-ключі;
- API-ключі OpenAI та Hugging Face;
- OAuth Client Secret;
- інші секретні налаштування.

Для локальної роботи передбачено `.env`, який потрібно виключити через `.gitignore`. Для демонстрації структури налаштувань використовується `.env.example`.

### Заплановані заходи безпеки

- **Паролі:** зберігання лише у вигляді хешів із використанням Argon2id.
- **JWT:** підпис HS256 із секретним ключем не менше 32 байтів, який передається через змінні середовища.
- **Refresh-токени:** зберігання у вигляді хешів у базі даних та відкликання під час виходу користувача.
- **HTTPS:** обов'язкове використання у production-середовищі.
- **HSTS та security headers:** налаштування захисних HTTP-заголовків.
- **CORS:** дозвіл запитів лише від визначених origins клієнта.
- **CSRF:** документування незастосовності для stateless Bearer API в ADR.
- **Mass assignment:** використання окремих вхідних DTO замість прямого прив'язування доменних моделей.
- **Обробка помилок:** відсутність розкриття внутрішніх деталей системи у відповідях користувачам.
