# OnlineLearning — платформа онлайн-навчання

**OnlineLearning** — інформаційна система для організації онлайн-навчання.

Проєкт передбачає створення платформи, яка об'єднує функціональність онлайн-курсів, уроків, зарахування студентів, відстеження навчального прогресу, тестування, real-time взаємодії та використання штучного інтелекту для перевірки відкритих відповідей.

---

## Мета проєкту

Метою проєкту є розробка багаторівневої інформаційної системи для організації дистанційного навчання.

Система повинна забезпечувати:

* створення та керування курсами;
* додавання навчальних матеріалів;
* організацію уроків;
* реєстрацію та авторизацію користувачів;
* зарахування студентів на курси;
* відстеження навчального прогресу;
* проведення тестування;
* розмежування прав доступу;
* обмін даними в реальному часі;
* надсилання сповіщень;
* формування сертифікатів;
* використання ШІ для перевірки відкритих відповідей.

## Опис шарів

### `OnlineLearning.Api`

Веб-рівень застосунку.

Відповідає за:

* HTTP-запити;
* API-контролери;
* маршрутизацію;
* Swagger;
* SignalR-хаби;
* взаємодію із Application-рівнем.

---

### `OnlineLearning.Application`

Містить бізнес-логіку застосунку.

Включає:

* сервіси;
* DTO;
* інтерфейси;

* правила взаємодії між компонентами.

---

### `OnlineLearning.Domain`

Містить основні об'єкти предметної області.

Передбачає:

* сутності;
* enum;
* базові типи;

---

### `OnlineLearning.Infrastructure`

Відповідає за роботу із зовнішніми та інфраструктурними компонентами.

Планується розмістити:

* Entity Framework Core;
* PostgreSQL;
* репозиторії;
* зовнішні API-клієнти;

---

### `OnlineLearning.Shared`

Містить спільні контракти та компоненти, які використовуються різними частинами системи.

# Як запустити локально

## Вимоги

Для запуску проєкту необхідні:

* **.NET SDK 10.0+**;
* **Visual Studio 2026** або **VS Code + C# Dev Kit**;
* `dotnet` CLI.

Для етапу роботи з базою даних додатково:

* **PostgreSQL 15+**.

---

## 1. Клонування репозиторію

```bash
git clone <URL>
cd OnlineLearning
```

---

## 2. Відновлення залежностей

Виконайте:

```bash
dotnet restore
```

Команда завантажить та відновить усі залежності проєкту.

---

## 3. Налаштування змінних середовища

Для етапів, де використовуються база даних, JWT або ШІ, необхідно створити файл `.env` на основі `.env.example`.

Наприклад:

```powershell
Copy-Item .env.example .env
```

Після цього відкрийте `.env` та замініть тестові значення на власні.

> **Важливо:** реальний файл `.env` не повинен потрапляти до репозиторію, оскільки він може містити секретні ключі та паролі.

---

## 4. Запуск API

Запустіть проєкт:

```bash
dotnet run --project src/OnlineLearning.Api
```

Після запуску API буде доступний за адресою, яку покаже консоль.

---

## 5. Swagger

Для перегляду та тестування API відкрийте:

```text
https://localhost:<port>/swagger
```

Swagger дозволяє переглядати доступні ендпоінти та виконувати тестові HTTP-запити.

Секретні дані не повинні зберігатися безпосередньо у вихідному коді.

| Змінна                       | Призначення                     |
| ---------------------------- | ------------------------------- |

# PostgreSQL

Починаючи з етапу 2, система використовуватиме PostgreSQL для зберігання даних.

Очікувана база даних:

```text
online_learning
```

Приклад підключення:

```env
ConnectionStrings__Default=Host=localhost;Port=5432;Database=online_learning;Username=postgres;Password=CHANGE_ME
```

Після інтеграції Entity Framework Core будуть використовуватися міграції для створення та оновлення структури бази даних.

---

# JWT-авторизація

На етапі 3 буде реалізована JWT-авторизація.

Передбачені ролі:

```text
admin
teacher
student
```

Кожна роль матиме власні дозволи та доступ до функціональності системи.

Приклад налаштувань:

```env
Jwt__Key=CHANGE_ME_SUPER_SECRET_32_CHARS_MIN
Jwt__Issuer=OnlineLearning
Jwt__Audience=OnlineLearning
```

> **Важливо:** значення `Jwt__Key` у реальному середовищі повинно бути замінене на власний секретний ключ.

# SignalR

Для real-time функціональності планується використання **SignalR**.

Передбачені сценарії:

```text
Новий навчальний матеріал
        ↓
SignalR
        ↓
Сповіщення студента
```

```text
Нова оцінка
        ↓
SignalR
        ↓
Сповіщення студента
```

```text
Зміна online-статусу
        ↓
SignalR
        ↓
Оновлення статусу користувачів
```

# Поточний API

На першому етапі реалізовано `CoursesController`.

Передбачені операції:

| Метод          | Операція                           |
| -------------- | ---------------------------------- |
| `GET`          | Отримання списку курсів            |
| `GET /{id}`    | Отримання курсу за ідентифікатором |
| `PUT /{id}`    | Оновлення курсу                    |
| `DELETE /{id}` | Видалення курсу                    |

На поточному етапі дані курсів зберігаються у статичному списку.

У наступному етапі вони будуть перенесені до PostgreSQL через Entity Framework Core.

# `.env.example`

Створити файл можна командою PowerShell:

```powershell
New-Item -Path .env.example -ItemType File
```

Вміст файлу:

```env

ConnectionStrings__Default=Host=localhost;Port=5432;Database=online_learning;Username=postgres;Password=CHANGE_ME

Jwt__Key=CHANGE_ME_SUPER_SECRET_32_CHARS_MIN
```

> **Увага:** наведені значення є лише прикладами. Реальні паролі та API-ключі необхідно вказувати локально у `.env`.
